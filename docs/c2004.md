## 🔍 Analiza i Plan Poprawy

### Problem 1: Template Paths (priorytet: WYSOKI)

**Opis:** Skaner wykrywa ścieżki z `{param}` z OpenAPI spec, ale testuje je dosłownie zamiast podstawiać testowe ID.

**Propozycja rozwiązania:**
- Dodać mechanizm "seed data" — testowe ID dla każdego zasobu
- Automatycznie tworzyć zasób (POST), zapamiętywać ID, następnie testować GET/PATCH/DELETE
- Konfigurowalne w `rebuild.yaml` jako `test_fixtures:`

### Problem 2: Autoryzacja (priorytet: WYSOKI)

**Opis:** POST/PUT/DELETE wymagają tokenu Bearer lub ciała JSON, testowane są bez nich → HTTP 405.

**Propozycja rozwiązania:**
- Dodać obsługę `auth:` w konfiguracji testowej
- Możliwość logowania i przechowywania tokenu sesji między requestami
- Testowe dane JSON dla każdego endpointu

### Problem 3: Deploy Failures (priorytet: KRYTYCZNY)

**Opis:** 5/6 dni nie przeszło fazy deploy. Brak szczegółów dlaczego.

**Do zbadania:**
- Sprawdzić logi deploy dla każdego dnia
- Czy to problem z docker-compose? Migracją? Zależnościami?
- Potrzebne lepsze logowanie przyczyn niepowodzenia deploy
